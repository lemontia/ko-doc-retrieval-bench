# 덕랩 임베딩 벤치

한국어 실무 질문으로 검색용 임베딩 모델을 비교하는 시험입니다. 질문 하나마다 정답 문서가 정해져 있고(known-item), 모델이 코퍼스 수천 건 가운데 정답 문서를 몇 위에 올렸는지로 점수를 매깁니다.

- 질문은 공개 데이터셋이 아니라 이 시험을 위해 새로 썼습니다. 실무 상담 말투·사연·검색어·일상어 네 가지 모양을 섞었습니다
- 질문과 정답 문서의 낱말 겹침에 상한(0.45)을 두었습니다. 낱말 맞추기만으로는 풀리지 않게 하려는 것입니다
- 평가판마다 숨긴 문항 50개가 따로 있습니다. 숨긴 문항은 이 저장소에 없고, 점수만 `export/` 의 「숨김」 묶음으로 공개합니다
- 모델 두 개를 비교할 때는 문항별로 짝지은 검정(McNemar)을 같이 냅니다

## 평가판 (v1 고정: 2026-10-18 ~ 10-19)

| 평가판 | 무엇 | 공개 문항 | 코퍼스 |
|---|---|---|---|
| 법령검색-v1 | 노동법령 조문 + 판례 | 100 | 5,714 |
| 세무-v1 | 국세 6법 + 세무 판례 | 99 | 6,445 |
| 민사-v1 | 민법 재산편·임대차·이자·제조물책임 + 판례 | 99 | 4,910 |
| 가사-v1 | 민법 친족·상속편·가사소송·가족관계등록 + 판례 | 99 | 1,519 |
| 형사-v1 | 형법·형사소송법·특가법·성폭력처벌법·도로교통 등 + 판례 | 100 | 5,618 |
| 개인정보소비자-v1 | 개인정보·정보통신망·전자상거래·약관·소비자기본·할부거래 + 판례 | 100 | 1,720 |
| 행정-v1 | 행정절차·심판·소송·국가배상·정보공개 등 + 판례 | 100 | 4,010 |

공개 문항 수가 99인 평가판은 정오표(`errata.yaml`)에서 한 문항을 뺀 것입니다. 코퍼스 크기가 서로 달라서 **평가판끼리 점수를 비교하지 않습니다.** 같은 평가판 안에서 모델끼리 비교합니다.

v1 고정 뒤에는 문항·정답·채점·입력 형식을 바꾸지 않습니다. 정답 오류는 `errata.yaml` 에만 더하고, 문항 파일은 처음 쓴 그대로 둡니다. 이 저장소의 `errata.yaml` 에서는 숨긴 문항에 대한 줄을 뺐습니다.

## 모델 (`models/*.yaml`)

| 파일 | 모델 | 방식 |
|---|---|---|
| bm25 | 낱말 기준선 (두 글자 조각 BM25) | — |
| gemma2 | google/embeddinggemma-2 (bf16) | 문서당 벡터 하나 |
| gemma2-gguf | 같은 모델의 GGUF Q8_0 (LM Studio) | 문서당 벡터 하나 |
| bge-m3 | BAAI/bge-m3 | 문서당 벡터 하나 |
| kure1 | nlpai-lab/KURE-v1 (bge-m3 를 한국어로 미세조정) | 문서당 벡터 하나 |
| kure2 | nlpai-lab/KURE-v2 (ColBERT, 토큰마다 벡터) | 다중 벡터 |

모델 파일 하나에 런타임·리비전·넣는 형식·라이브러리 버전(`requires`)이 다 들어 있습니다. `run` 은 `requires` 로 임시 환경을 띄워 그 안에서 다시 실행합니다(모델마다 맞는 라이브러리 버전이 서로 다릅니다).

문항별 순위, r@1·r@5·MRR, 질문 모양별 점수, 숨긴 문항 점수는 `export/` 에 있습니다.

## 쓰는 법

```bash
uv sync
uv run bench.py run --model kure2                 # 평가판 전부. --suite 법령검색-v1 로 하나만
uv run bench.py compare kure2 kure1               # 평가판별 지표 + McNemar (각 모델의 가장 최근 기록)
uv run bench.py export                            # public: yes 인 평가판만 export/<평가판>.json
uv run python test_bench.py
```

- 결과는 `results.jsonl` 에 한 줄씩 더해집니다. 문항별 순위까지 남습니다
- 순위: 조각 점수 → 문서 점수는 조각 가운데 최고값 → 정답 문서의 순위. **점수가 같으면 정답을 뒤로** 셉니다
- 묶는 방식도 시험 조건입니다. 같은 모델이라도 묶음 구성이 바뀌면 Apple GPU(MPS)에서 벡터가 조금 달라져 순위가 바뀔 수 있습니다. KURE 는 토큰 길이 순(stable sort)으로 묶습니다
- `gemma2-gguf` 는 LM Studio 에 모델을 올려 두고 `url` 을 자기 환경에 맞게 고쳐야 합니다
- `tools/machine.py`: 색인 시간·질문 하나 처리 시간·메모리 최대 증가분·저장 공간을 같은 방법으로 잽니다

## 이 저장소에 없는 것

- 숨긴 문항과 그 정답
- 평가판을 만든 도구(정답 문서를 뽑는 스크립트). 시드와 함께 공개하면 숨긴 문항의 정답 문서를 다시 뽑을 수 있어서 뺐습니다
- 원본 기록(`results.jsonl`). 숨긴 문항별 순위가 들어 있어서 뺐습니다. 공개용 결과는 `export/` 입니다

`export/` 의 기록은 원본 정오표(숨긴 문항 줄 포함)로 잰 것이라, 여기서 다시 재면 기록의 `errata_hash` 가 export 와 다르게 나옵니다. 공개 문항 점수는 같습니다.
